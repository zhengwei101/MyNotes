# Redis 数据持久化与主从集群

## 一、主从复制

通过增加冗余从库，提高实例可用性。具体复制方式如下：

1. **全量复制**：涉及 RDB、复制缓冲区。

2. **增量复制**：依赖复制积压缓冲区。

## 二、哨兵机制

通过哨兵监控主库心跳，实现主库故障判断和自动切换。详细内容如下：

**心跳与下线判断**：

1. **主客观下线**：主观下线由哨兵自行判断；客观下线指超过 quorum 个哨兵判断为主观下线。

2. **quorum 机制**：在判断客观下线时起关键作用。

**故障切换**：

1. **Leader 选举**：采用分布式共识，raft 协议进行选举。

2. **选主**：从符合条件的节点中选出新的主库。

3. **主从切换**：完成新主库和从库之间的角色转换。

## 三、哨兵监控主库心跳的具体情况

1. **主观下线**：哨兵自行判断主库状态，若满足一定条件则标记为主观下线。

2. **客观下线**：当超过 quorum 个哨兵都判断主库为主观下线时，主库被认定为客观下线。

## 四、总结

Redis 的可用性涵盖数据可用和实例可用两个方面：

**数据持久化**：实现数据高可用。其中，AOF 通过记日志的方式保证数据高可用，但会对性能产生一定影响，需注意落盘配置；RDB 通过内存快照实现数据备份，不过要留意实例大小对 fork 操作的影响。

**主从集群**：实现实例高可用。主从复制包括第一次复制时的全量复制以及网络断开重连后的增量复制。

**哨兵机制**：实现自动故障切换，其关键点在于下线判断和 Leader 选举。同时需要注意，主从复制不保证数据强一致性；在故障切换时可能会出现脑裂现象，建议考虑 fence 机制来避免相关问题。
